知识推理 · 精炼学习笔记

目标：快速抓住规则推理 / 本体推理 / Embedding 推理的核心，能说清「已知什么、推出什么、靠不靠谱」。

一句话总览

知识推理 = 在已有知识上，自动得到未显式写出的新事实，或发现矛盾。

要点 本质 输出
规则推理 IF-THEN / 产生式、图规则 新三元组、告警、标签
本体推理 基于 RDFS/OWL 公理的逻辑推导 类型补全、一致性结论
Embedding 向量空间上的统计推断 链接预测、相似度、候选补全 
显式知识（库里写明的）
        + 规则 / 公理 / 向量模型
        ↓
隐含知识（推断出的）或 冲突（不一致）

与上下游：

表示（公理/模式）+ 存储（事实） → 推理（补全/校验） → 应用（问答、风控、推荐）
获取（抽出来的）也可能噪声大 → 推理前常需融合与质检

三类关系（务实）：规则可解释、本体可校验、Embedding 能补洞；生产常组合使用。

1. 规则推理（Rule-based Reasoning）

核心定义

用人工或半自动定义的逻辑规则，匹配已有事实后触发结论（或动作）。

经典形态（产生式）：

IF  条件模式成立
THEN 断言新事实 / 触发告警 / 写入标签

证券最小例子

规则 R1（控股传递，简化）：
  IF  (?a)-[:CONTROLS]->(?b) AND (?b)-[:CONTROLS]->(?c)
  THEN (?a)-[:CONTROLS]->(?c)          # 或标记「间接控股」

规则 R2（上市推断）：
  IF  (?x)-[:LISTED_AS]->(?s:Stock)
  THEN (?x) 属于 ListedCompany

规则 R3（风控）：
  IF  (?p)-[:HAS_EXECUTIVE]->(?c1) AND (?p)-[:HAS_EXECUTIVE]->(?c2)
      AND (?c1)-[:COMPETES_WITH]->(?c2)
  THEN 告警「同高管关联竞品公司」

常见规则载体

载体 说明 典型场景
业务代码 if/else 最直观 小规则集、强业务定制
Cypher 定时/触发查询 在 Neo4j 里跑模式匹配 本仓库可自然扩展
规则引擎 Drools 等 规则很多、要热更新
逻辑规则语言 Datalog、SWRL、SPARQL CONSTRUCT 学术/语义网、可声明式

Neo4j 风格「规则」示例（间接关联）：

MATCH (a:Company)-[:CONTROLS]->(:Company)-[:CONTROLS]->(c:Company)
MERGE (a)-[:CONTROLS {inferred:true, depth:2}]->(c)

注意：盲目物化所有传递闭包可能边爆炸；常查询时计算或只物化高频规则。

规则推理的强项与坑

强项 坑
可解释（能指出命中哪条规则） 规则冲突、维护成本高
易嵌入风控/合规 覆盖长尾难
不依赖大规模标注 传递/递归要控制深度

速记

  • 规则推理回答：「按人定的 IF-THEN，从图里推出新结论」
  • 适合：明确业务逻辑、要审计解释 的场景

2. 本体推理（Ontology-based Reasoning）

核心定义

依据本体中的公理（子类、互斥、属性特征、等价等），由推理器对知识库做分类（分类学推理）与一致性检查。

与规则推理的差别（直觉）：

规则推理 本体推理
知识从哪来 业务专家写 IF-THEN 本体工程师写 OWL/RDFS 公理
引擎 规则引擎 / Cypher / 代码 HermiT、Pellet、ELK…
典型结果 新业务边、告警 实例归属类、属性补全、不一致
风格 偏「过程/产生式」 偏「描述逻辑」

二者可重叠（SWRL 等把规则挂到 OWL 上），入门先分开记。

先对齐词汇：TBox 公理 × ABox 事实

（详见 知识表示 · TBox/ABox；初学者需要会认这两个词。）

本体推理里扮演的角色
TBox 提供「规矩」：子类、互斥、传递……推理器主要靠它推导
ABox 提供「已知事实」：谁属于哪类、谁连着谁；也被补全或拿去验伤 
TBox（公理） + ABox（显式事实）  --推理器-->  隐含事实 或  不一致告警

你已经见过的最小例子

见 docs/examples/securities-mini.ttl：

# TBox
:ListedCompany rdfs:subClassOf :Company .
:Person owl:disjointWith :Company .
# ABox
:Moutai a :ListedCompany .

ABox 显式断言：茅台是 ListedCompany
结合 TBox 推出：茅台也是 Company（子类继承）——这是往 ABox 补类型
若再向 ABox 断言茅台是 Person → 不一致（与 TBox 的互斥公理冲突）

这就是本体推理在工程上的两大用途：

  1. 补全 ABox：少写、多得（类型、等价属性等）
  2. 用 TBox 验伤：发现互相打架的数据

常见公理 → 推理直觉

公理 直观效果
subClassOf 子类实例也是父类实例
disjointWith 两类不能同时成立
equivalentClass 两类实例互相归属
属性 Transitive a-r->b-r->c ⇒ a-r->c
属性 Symmetric a-r->b ⇒ b-r->a
属性 Functional 同一主体该属性最多一个值
domain / range 用了属性 ⇒ 端点应属某类（视推理配置）

工程怎么跑（三步）

  1. 用 Protégé 打开本体 + 实例（或 RDF 库加载）
  2. 启用推理器（HermiT / Pellet…）
  3. 查看 Inferred 视图：多出来的类型、或红色不一致

和 Neo4j 本项目的关系

OWL 本体推理 本项目现状
推理器自动推 ListedCompany ⇒ Company 入库时可直接打多标签，或应用层约定
disjointWith 查冲突 需自写校验 / 尚未做完整 OWL 栈
传递属性 可用 Cypher 路径查询模拟

务实架构：Neo4j 存运行事实；关键公理用规则/校验实现；完整 OWL 推理按需上（不是每个业务系统都要上推理器）。

速记

  • 本体推理回答：「按公理，机器帮你归类、补全、找矛盾」
  • 关键词：分类 + 一致性（classification + consistency）
  • 口诀：TBox 定规矩，ABox 填事实，推理器两边一起看

3. Embedding 推理（表示学习 / 链接预测）

核心定义

把实体与关系编成向量后，用几何/评分函数判断「某条三元组是否可能成立」，从而做补全与发现——这是统计意义上的「推理」，不是逻辑证明。

已知：许多 (h, r, t) 训练向量
询问：贵州茅台  ?R?  某公司   或   茅台 -CONTROLS-> ?
输出：候选尾实体 / 关系 的排序与分数

和逻辑推理差在哪

规则/本体推理 Embedding 推理
依据 符号逻辑 数据统计规律
结论性质 对/错（在公理下） 可能/置信度
可解释性 强 通常较弱
长尾/缺失 规则没写就推不出 仍可能「猜」出候选
噪声 脏数据易导致矛盾 对噪声相对更稳，但会错得隐蔽

经典直觉（只记一个就够）

TransE：希望真实三元组满足

h⃗ + r⃗ ≈ t⃗

头实体向量加上关系向量，接近尾实体向量；距离越近，越像「真关系」。

由此可做：

  1. 链接预测（Link Prediction）：补缺失边
  2. 实体排序：给定头和关系，谁最可能是尾
  3. 三元组分类：这条边像不像真的

证券场景怎么用（概念级）

任务 Embedding 用法
潜在竞品/关联方发现 向量近邻 + 人工复核
图谱补全 预测可能的 BELONGS_TO / RELATED_TO
研报实体链接辅助 文本向量 ↔ 实体向量对齐

务必加护栏：高分候选 ≠ 事实；落库前要阈值、规则或人工确认。

和「知识表示」里 Embedding 的关系

  • 表示笔记强调：Embedding 是一种表示形式
  • 本笔记强调：用该表示去做推断/补全（应用层叫「推理」）

同一技术，两个视角：存成向量 vs 用向量猜未知边。

速记

  • Embedding 推理回答：「按向量几何，哪些未知三元组比较像真的」
  • 定位：召回与发现，不是合规级终审

三条路线怎么组合（工程配方）

1) Embedding / 检索   → 提出候选边、候选实体
2) 规则推理           → 业务过滤、风控、可解释结论
3) 本体推理 / 校验     → 类型一致性、互斥冲突检查
4) 写入 Neo4j         → 标记 inferred=true、来源与置信度
需求 更优先
监管可解释、强约束 规则 + 本体校验
覆盖率、发现隐藏关联 Embedding
在线多跳查询 Cypher 路径（即时「推」可不物化）

查询时「即时推理」示例（不落库）：

// 间接控股路径（深度 2）
MATCH (a:Company)-[:CONTROLS]->()-[:CONTROLS]->(c:Company)
WHERE a.name = $name
RETURN DISTINCT c.name AS indirect

5 分钟自测

  1. 知识推理与知识获取的差别？
  2. 规则推理一条证券例子；物化传递闭包有何风险？
  3. 本体推理中 TBox / ABox 各扮演什么角色？两大用途？ListedCompany ⊑ Company 能推出什么？
  4. Embedding「推理」为何不是逻辑证明？TransE 直觉？
  5. 生产上三者如何分工最稳妥？

参考答案要点：
①获取从文本抽事实；推理从已有事实推新知/找矛盾
②如控股传递；边可能爆炸
③TBox=公理规矩，ABox=实例事实；补全 ABox + 用 TBox 验一致性；茅台也是 Company
④统计相似；h+r≈t
⑤向量召回 → 规则解释/过滤 → 本体或约束校验 → 再入库

建议学习顺序

  1. 用 .ttl + Protégé 亲眼看一次 Inferred 类型 / 不一致
  2. 在 Neo4j 写 2～3 条 Cypher「规则」（间接控股、由股票推断上市）
  3. 分清 查询时计算 vs 物化推断边
  4. 有补全需求时再学 链接预测 / TransE 直觉
  5. 回看知识表示中的公理表，对照「能推出什么」
