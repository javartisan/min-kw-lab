知识问答 · 精炼学习笔记

目标：快速抓住 KBQA / 语义解析 / GraphRAG 的核心，能说清「自然语言问题如何变成图谱上的答案」。

一句话总览

知识问答（KGQA） = 用自然语言提问，基于知识图谱返回可追溯、可解释的答案（实体、关系、子图或聚合结果）。

要点 本质 输出
KBQA 问题 → 图上结构化查询 → 答案 「茅台属于什么行业？→ 白酒」
语义解析 把问句编译成 Cypher/SPARQL 可执行查询语句
GraphRAG 检索子图/路径作上下文再生成 自然语言答复 + 证据边 
用户问句
  → 理解（意图/实体/约束）
  → 查图（Cypher / SPARQL / 路径）
  → （可选）推理补全
  → 答案生成 + 证据展示

在七大方向中的位置：表示～融合把图谱建好；问答是面向人的核心应用出口之一。

1. KBQA（Knowledge Base Question Answering）

核心定义

以知识库/知识图谱为唯一或主真相来源的问答：答案应能在图上找到支撑三元组或路径，而不是凭空生成。

问题类型（由易到难）

类型 例子 图上怎么做
单跳事实 茅台的股票代码？ 一跳 LISTED_AS
多跳 丁雄军任职公司属于什么行业？ Person→Company→Industry
约束/聚合 白酒行业有哪些公司？ BELONGS_TO 反向 + 列表
比较/是否 A 与 B 是否竞争？ 查有无 COMPETES_WITH
路径解释 A 如何关联到 B？ 最短路径 / 路径枚举

经典流水线

1. 实体链接：问句里的「茅台」→ 图节点 贵州茅台
2. 关系/意图识别：问的是代码？行业？高管？
3. 查询构造：生成 Cypher/SPARQL 或填槽模板
4. 执行与排序：跑图查询，多候选时打分
5. 答案包装：返回值 + 证据三元组/路径

与「聊天模型直接答」的差别

纯 LLM KBQA
真相来源 参数记忆 图谱显式事实
可追溯 弱 强（可点开边）
时效 易过时 随库更新
幻觉 高风险 无结果就说「库中无」

证券场景更需要 KBQA 或 GraphRAG，避免「瞎编董事长」。

速记

  • KBQA 回答：「答案必须能在图上指出来」
  • 评价常看：答案对不对、能否指出证据路径

2. 语义解析（Semantic Parsing → 图查询）

核心定义

把自然语言映射为形式化查询（对 Neo4j 即 Cypher，对 RDF 即 SPARQL）。是 KBQA 的「编译器」核心。

三条工程路线

路线 做法 优缺点
模板/槽位 「X的股票代码」→ 固定 Cypher 准、可控；覆盖窄
语义解析模型 学 NL→查询AST/语句 泛化较好；需标注
LLM 生成查询 提示生成 Cypher 再执行 快；必须校验防注入/胡写

最小证券模板例子

问句：贵州茅台属于什么行业？

MATCH (c:Company {name: $name})-[:BELONGS_TO]->(i:Industry)
RETURN i.name AS answer

问句：宁德时代的董事长是谁？

MATCH (c:Company {name: $name})-[:HAS_EXECUTIVE]->(p:Person)
RETURN p.name AS answer

问句：和贵州茅台竞争的公司有哪些？

MATCH (c:Company {name: $name})-[:COMPETES_WITH]-(x:Company)
RETURN DISTINCT x.name AS answer

安全与落地要点

  1. 参数化：名称等用参数绑定，禁止字符串拼接用户输入进查询
  2. 白名单：只允许只读查询 / 限制深度与 LIMIT
  3. 校验：LLM 生成的 Cypher 先 AST/关键字检查再执行
  4. 无结果策略：明确「图谱暂无」，可降级检索文档

速记

  • 语义解析回答：「人话怎么变成可执行的图查询」
  • 入门用模板，进阶用模型/LLM + 护栏

3. GraphRAG（图增强检索生成）

核心定义

在 RAG（检索增强生成）中，检索对象不只是文本块，而是子图、路径、社区摘要，再交给 LLM 组织自然语言答案。

问句
 → 链实体 / 扩邻居 / 抽相关路径
 → 把三元组或子图序列化成上下文
 → LLM 生成答复（要求引用图内事实）

何时用 GraphRAG 而不是纯 KBQA

更适合 GraphRAG 更适合纯 KBQA
「解读一下茅台的产业位置」 「茅台代码是多少」
需要组织多跳证据成段落 答案是单个槽位值
图谱稀疏，要结合文档 图上事实完整且结构化

与本仓库的衔接

当前前端是可视化 + 关键词检索，尚未做问答框。最小演进：

  1. 模板 KBQA API：POST /api/qa { question } → 匹配模板 → Cypher → JSON 答案
  2. 答案面板展示证据边（复用 graph 接口子图）
  3. 再视需要加 LLM 生成叙述（GraphRAG）

速记

  • GraphRAG 回答：「先取真子图，再让模型说人话」
  • 原则：图管事实，模型管表达

②关系跳数与路径长度

建议学习顺序

  1. 罗列 10 个证券高频问句，标成单跳/多跳
  2. 为每类写一条 Cypher 模板
  3. 做实体链接（问句mention→节点名）
  4. 再考虑 LLM 生成查询或 GraphRAG 叙述
  5. 始终返回证据边，方便审计
